# bool-cAST
## 1. Project Overview
**bool-cAST** is a small Boolean expression parser and interpreter written in **C**.

The project takes a Boolean expression as input, parses it using **Flex** and **Bison**, builds an **Abstract Syntax Tree (AST)** representing the expression, and finally evaluates the AST to produce a Boolean result.

The main goal of the project is to experiment with:
- lexical analysis with Flex;
- parsing with Bison;
- Abstract Syntax Trees;
- recursive interpretation of an AST;
- modular C project organization;
- automated testing with assertions;
- building the project with a Makefile.

The project currently supports Boolean constants and several logical operators.

---
## 2. Supported Expressions

The following Boolean values and operators are currently supported:
| Syntax | Meaning |
|---|---|
| `true` | Boolean true |
| `false` | Boolean false |
| `!A` | NOT |
| `A && B` | AND |
| `A \|\| B` | OR |
| `A ^ B` | XOR |
| `A => B` | Implication |
| `A <=> B` | Equivalence |
| `(A)` | Grouping |

Parentheses can be nested, allowing expressions such as:
```text
((true && false) || (true ^ false))
```
The exact precedence and associativity of the operators are defined in the Bison grammar.

### `ASTNode`
The AST module defines the different types of nodes used to represent Boolean expressions.

The main node types are:
```text
AST_BOOL
AST_NOT
AST_AND
AST_OR
AST_IMPLIES
AST_EQU
AST_XOR
```
Boolean constants are stored directly in the node, while unary and binary operators contain pointers to their child nodes.

For example, the expression:
```text
true && false
```
can be represented approximately as:
```text
       AND
      /   \
    BOOL  BOOL
     |      |
   true    false
```

## 4. Parsing Process
The parsing process is divided into two main stages: lexical analysis and syntax analysis.
### 4.1 Lexical Analysis
The lexer is implemented in `lexer.l` using **Flex**.

It converts the input string into tokens that can be understood by the parser.

For example:
```text
true && false
```
is converted approximately into:
```text
TRUE
AND
FALSE
```
Whitespace is ignored by the lexer.

Operators and parentheses are also converted into their corresponding tokens.

---
### 4.2 Syntax Analysis
The grammar is implemented in `parser.y` using **Bison**.

Bison receives the tokens produced by Flex and checks whether they form a valid Boolean expression.

During parsing, semantic actions construct the AST.

For example:
```text
(true && false) || true
```

is transformed into a tree whose structure reflects the operators and their operands.

The public parser interface is exposed through:
```c
ASTNode *parser(const char *input);
```
This function takes an expression as a string and returns the root of the generated AST.

If the expression cannot be parsed, `NULL` is returned.

---
## 5. Interpretation

Once the AST has been constructed, it is evaluated recursively by the interpreter.

The interpreter exposes the following interface:
```c
bool interpreter(const ASTNode *node);
```
The AST is passed as a `const` pointer because the interpreter only reads the tree; it does not modify it.

The evaluation is based on the node type.

For example:
```text
AST_BOOL
    → return its Boolean value

AST_NOT
    → evaluate its child and negate the result

AST_AND
    → evaluate both children and apply AND

AST_OR
    → evaluate both children and apply OR

AST_IMPLIES
    → evaluate A and B, then compute !A || B

AST_EQU
    → evaluate both operands and compare them

AST_XOR
    → evaluate both operands and check that they differ
```
The interpreter is therefore a recursive tree traversal.

---
## 6. Memory Management
AST nodes are dynamically allocated while parsing.

Once an expression has been evaluated, the AST is no longer needed and is released using:
```c
ast_free(ast);
```
This keeps the ownership of the generated tree explicit and prevents the AST from remaining allocated after evaluation.

## 7. Building the Project
The project uses a `Makefile` to automate compilation.

The main requirements are:
- GCC or another C17-compatible compiler;
- GNU Make;
- Flex;
- Bison;
- the Flex library (`libfl`).
To build the main executable:
```bash
make
```
The executable is generated as:
```text
build/bool-cAST.out
```
---

## 8. Using the Program
The program expects a Boolean expression as a command-line argument.

For example:
```bash
make run "true"
```

Output:
```text
true
```
Another example:
```bash
make run "true && false"
```
Output:
```text
false
```
Parenthesized expressions are supported:
```bash
make run "(true || false) && true"
```
Output:
```text
true
```
More complex expressions can also be evaluated:
```bash
make run "((true && false) || (true ^ false))"
```
Output:
```text
true
```
If the expression is invalid, the parser reports a syntax error and the program reports that the expression is invalid.

## 9. Testing
The project contains a separate test executable.

Tests can be run with:
```bash
make test
```
The tests use the standard C `assert()` mechanism.

They evaluate expressions through the same parsing and interpretation pipeline as the main program.

The test suite covers:
- Boolean constants;
- unary NOT;
- AND;
- OR;
- XOR;
- implication;
- equivalence;
- parentheses;
- nested parentheses;
- combinations of several operators;
- deeply nested expressions.
For example:
```c
assert(eval("true && false") == false);
assert(eval("(true || false) && true") == true);
assert(eval("!((true && false) || true)") == false);
```
A successful test run produces no assertion failure.

## 11. Development Approach
The project was developed incrementally.

The main steps were:

1. Define the AST representation.
2. Implement AST creation and destruction.
3. Define the Boolean grammar with Bison.
4. Implement lexical analysis with Flex.
5. Connect Flex and Bison to construct the AST.
6. Implement the recursive interpreter.
7. Create a command-line interface.
8. Add automated evaluation tests.
9. Improve the Makefile to separate the main executable from the test executable.
10. Test increasingly complex expressions, including nested parentheses.

The project was intentionally kept relatively small in order to focus on the interaction between the lexer, parser, AST, and interpreter.

## 13. Limitations and Possible Improvements
This project is intentionally simple and has several possible areas for improvement.

Possible future developments include:
- adding Boolean variables;
- allowing variable assignments;
- implementing a symbol table;
- providing better syntax error messages;
- improving memory/error handling;
- adding more extensive invalid-input tests;
- separating the parser interface from generated Bison files more cleanly;
- adding automated testing to a CI workflow;
- extending the language with additional logical operators.
The current implementation is primarily intended as a learning project around parsing, ASTs, and interpretation rather than as a complete Boolean expression language.
---

## 14. Conclusion
**bool-cAST** is a small C project demonstrating how a textual Boolean expression can be transformed into an Abstract Syntax Tree and evaluated recursively.

The project combines:
```text
Input expression
       │
       ▼
     Flex
       │
       ▼
    Tokens
       │
       ▼
    Bison
       │
       ▼
      AST
       │
       ▼
  Interpreter
       │
       ▼
 true / false
```
Although the project is relatively small, it provides a practical example of how lexical analysis, parsing, tree-based representations, recursive evaluation, memory management, and automated testing can be combined in a C program.
